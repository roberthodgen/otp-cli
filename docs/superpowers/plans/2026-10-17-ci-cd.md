# CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add pull-request verification and tag-driven, signed cross-platform GitHub releases for the OTP CLI.

**Architecture:** A single PR workflow restores, builds, and tests the existing .NET 10 solution in one Ubuntu job. A tag-triggered release workflow validates the tag against `package.json` while producing Windows/Linux binaries, then produces signed/notarized macOS ZIPs only after validation succeeds, and finally creates the GitHub release. GitHub’s release-note configuration and the two release documents provide the supporting user-facing contract.

**Tech Stack:** GitHub Actions, .NET 10 CLI, GitHub CLI, Node.js package metadata, macOS `security`, `codesign`, `ditto`, and `xcrun notarytool`.

**Spec:** `docs/superpowers/specs/2026-10-17-ci-cd-design.md`

## Global Constraints

- Run PR CI for `opened`, `reopened`, and `synchronize` pull-request events without a base-branch filter.
- Use .NET `10.0.x`, `otp-cli.slnx`, and Release configuration for all CI/CD .NET commands.
- Do not add a no-op E2E step; add a distinct named E2E step only when an E2E suite exists.
- Trigger releases only for pushed `v*` tags and fail unless the tag equals `v<package.json version>`.
- Release exactly `otp_win-x64.exe`, `otp_linux-x64`, `otp_macos-x64.zip`, and `otp_macos-arm64.zip`.
- Use native AOT and the `release` environment for macOS signing/notarization; ZIP artifacts are not stapled.
- Do not create or publish NuGet packages.
- Preserve existing user changes to `docs/releasing.md` and `otp-cli.slnx`; fold the staged release-document correction into the focused documentation task without reverting it.

## Review Focus

- PRs targeting a non-`main` branch must still trigger verification; Task 1 checks the unfiltered PR trigger.
- The test task must run only after a successful Release build and must not silently rebuild; Task 1 checks the ordered build/test commands and both `--no-build` and `--no-restore`.
- A tag such as `v0.0.1` with package version `0.0.0` must halt before artifact/release creation; Task 3 exercises the exact mismatch guard in a shell.
- A missing Apple signing value must fail the protected macOS job rather than bypass signing/notarization; Task 3 checks every required secret is mapped to its signing/notarization step.
- GitHub releases must contain exactly the four documented asset names; Task 3 checks artifact upload paths and the `gh release create` input.

**Files:**

**Interfaces:**
- Consumes: `otp-cli.slnx`; GitHub pull-request event payloads.
- Produces: one required/checkable GitHub Actions job named `verify` that reports restore, build, and test status.

Define the workflow name as `✅ .NET`, trigger only on `pull_request` event types `opened`, `reopened`, and `synchronize` with no `branches` key, and create the `verify` job on `ubuntu-latest`.

- [ ] **Step 2: Add source checkout and .NET setup steps**

Use `actions/checkout@v4` and `actions/setup-dotnet@v4` with `dotnet-version: 10.0.x`.

- [ ] **Step 3: Add the ordered restore, Release build, and unit-test steps**

Run, in this exact order:

```yaml
dotnet restore otp-cli.slnx
dotnet build otp-cli.slnx --configuration Release --no-restore
dotnet test otp-cli.slnx --configuration Release --no-build --no-restore
```

Name the test step `✅ Test`. Do not add an E2E placeholder.

- [ ] **Step 4: Validate the workflow structure and current solution commands**

Run:

```bash
ruby -e 'require "yaml"; w = YAML.load_file(".github/workflows/pr.yml"); pr = (w["on"] || w[true])["pull_request"]; abort unless pr["types"] == %w[opened reopened synchronize]; abort if pr.key?("branches"); runs = w["jobs"]["verify"]["steps"].map { |step| step["run"] }.compact; abort unless runs == ["dotnet restore otp-cli.slnx", "dotnet build otp-cli.slnx --configuration Release --no-restore", "dotnet test otp-cli.slnx --configuration Release --no-build --no-restore"]'
make build
make test
```

Expected: YAML parses, the PR trigger and no-rebuild test command are present, and build/tests pass.

- [ ] **Step 5: Commit the PR workflow**

### Task 3: Add the versioned multi-platform release workflow

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: a pushed `v*` tag; `package.json` `version`; the protected `release` environment; documented Apple signing/notarization secrets.
- Produces: `cli-non-macos` and `cli-macos` workflow artifacts, then a GitHub release containing four named CLI assets.

- [ ] **Step 1: Define the release trigger, permissions, and job dependency graph**

Trigger on `push.tags: [v*]`, grant workflow-level `contents: write`, and define `build`, `macos`, and `publish` jobs. Make `macos` depend on `build` so an invalid tag cannot begin signing/notarization; make `publish` depend on both jobs; and set `environment: release` on `macos` and `publish`.

- [ ] **Step 2: Implement tag/package-version validation before Ubuntu publishing**

In the Ubuntu `build` job, checkout with `fetch-depth: 0`, set up .NET `10.0.x`, restore/build/test `otp-cli.slnx` in Release, then read `package.json` with `node -p "require('./package.json').version"`. Compare it to `GITHUB_REF_NAME` and exit nonzero with a clear expected-tag diagnostic unless the tag is exactly `v$PACKAGE_VERSION`.

- [ ] **Step 3: Publish and upload Windows/Linux CLI artifacts**

Create `build/`, then run `dotnet publish src/Cli/RobertHodgen.Otp.Cli.csproj` in Release for `win-x64` and `linux-x64`, passing `/p:Version=$PACKAGE_VERSION`. Copy `src/Cli/bin/Release/net10.0/win-x64/publish/otp.exe` and `src/Cli/bin/Release/net10.0/linux-x64/publish/otp` to the exact required names `build/otp_win-x64.exe` and `build/otp_linux-x64`. Upload only these files with `actions/upload-artifact@v4`, artifact name `cli-non-macos`, and `if-no-files-found: error`.

- [ ] **Step 4: Implement the protected macOS AOT build, signing, and notarization job**

Checkout with full history, set up .NET `10.0.x`, restore the solution, and read `PACKAGE_VERSION` from `package.json`. Publish `src/Cli/RobertHodgen.Otp.Cli.csproj` for `osx-x64` and `osx-arm64` with Release, `PublishAot=true`, and `/p:Version=$PACKAGE_VERSION`. Copy `src/Cli/bin/Release/net10.0/osx-x64/publish/otp` and `src/Cli/bin/Release/net10.0/osx-arm64/publish/otp` to `build/otp_macos-x64` and `build/otp_macos-arm64`.

Import the base64 P12 into `build.keychain`, make it the unlocked default keychain, set its partition list for codesigning, and list valid identities. Map these secrets only through `env`: `APPLE_CERTIFICATE_P12_BASE64`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_KEYCHAIN_PASSWORD`, `APPLE_CODESIGN_IDENTITY`, `APPLE_ID`, `APPLE_TEAM_ID`, and `APPLE_APP_SPECIFIC_PASSWORD`.

Sign both raw executables with `codesign --force --timestamp --options runtime --sign`, verify them with `codesign --verify --strict --verbose=2`, create the two ZIPs with `ditto -c -k`, and submit each ZIP with `xcrun notarytool submit ... --wait`. Do not staple the ZIPs. Upload exactly the two ZIPs with artifact name `cli-macos` and `if-no-files-found: error`.

- [ ] **Step 5: Implement the release publication job**

Download both artifacts into `build` with `actions/download-artifact@v4` and `merge-multiple: true`. Set `GH_TOKEN: ${{ github.token }}` and run:

```bash
gh release create "$GITHUB_REF_NAME" build/* --generate-notes --title "$GITHUB_REF_NAME"
```

Do not add NuGet login, packing, publishing, symbols, or OIDC permissions.

- [ ] **Step 6: Exercise workflow guards and inspect release configuration**

Run:

```bash
ruby -e 'require "yaml"; YAML.load_file(".github/workflows/release.yml")'
if PACKAGE_VERSION=0.0.0 GITHUB_REF_NAME=v0.0.1 bash -c 'if [ "$GITHUB_REF_NAME" != "v$PACKAGE_VERSION" ]; then exit 1; fi'; then echo 'mismatched tag unexpectedly passed' >&2; exit 1; fi
grep -q 'otp_win-x64.exe' .github/workflows/release.yml
grep -q 'otp_linux-x64' .github/workflows/release.yml
grep -q 'otp_macos-x64.zip' .github/workflows/release.yml
grep -q 'otp_macos-arm64.zip' .github/workflows/release.yml
for secret in APPLE_CERTIFICATE_P12_BASE64 APPLE_CERTIFICATE_PASSWORD APPLE_KEYCHAIN_PASSWORD APPLE_CODESIGN_IDENTITY APPLE_ID APPLE_TEAM_ID APPLE_APP_SPECIFIC_PASSWORD; do grep -q "$secret" .github/workflows/release.yml || exit 1; done
! grep -q 'stapler' .github/workflows/release.yml
grep -q -- '--generate-notes' .github/workflows/release.yml
```

Expected: YAML parses; the simulated mismatched tag exits 1; all four asset names, the notarization credential, and generated-notes release command are present.

- [ ] **Step 7: Commit the release workflow**

```bash
git add .github/workflows/release.yml
git commit --only .github/workflows/release.yml -m "ci: publish tagged CLI releases"
```
